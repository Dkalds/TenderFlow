# Improvement Backlog

Lista viva de mejoras conocidas, priorizadas. **Diseñada para que un agente pueda elegir un ítem y trabajarlo sin pedir contexto extra al usuario.**

## Convenciones

- **Prioridad**: P0 (urgente / bloquea) · P1 (alta) · P2 (media) · P3 (nice-to-have).
- **Riesgo**: bajo (cambio aislado) · medio (afecta varios módulos) · alto (toca core / migra schema / cambia contrato).
- Si añadís un ítem nuevo, copiá la plantilla del final.
- **Estado actual** es la primera línea de cada ítem y dice lo que queda **hoy**, con fecha y clase: `código` (hay que escribirlo), `propietario` (el código está; falta una acción que solo hace el dueño), `medir` (falta mirarlo en producción) o `mixto` (más de una, dicho cuáles). Se **reescribe** cada vez que el ítem avanza; las notas de progreso con fecha quedan debajo como historia. El **Problema** no se toca: es el porqué del ítem, no su estado. Quien proponga o planifique a partir de este fichero lee el Estado actual, con `make backlog-estado` (AGENTS.md §0). `check_backlog_freshness.py` falla si un ítem no lo tiene o si alguna de sus notas con fecha es posterior a él: añadir progreso obliga a reescribirlo. También falla si el Estado actual cita entre comillas invertidas una ruta del repo que no existe: nombrar el fichero o símbolo comprobado es lo que hace verificable la frase.
- Lo que solo puede hacer el propietario se lista además en [Acciones del propietario](#acciones-del-propietario), con enlace al ítem: se borra de ahí en el mismo cambio que cierra la acción.
- Al cerrarlo, no lo dejes tachado aquí: **borralo**. El rastro es el PR que lo resuelve («Cierra: <título>» y la medición en su descripción); una decisión o un procedimiento duraderos van a un ADR, un RFC o un runbook, y el backlog solo enlaza. Las secciones P0-P3 contienen **solo ítems abiertos**.
- El histórico anterior al 2026-11-06 está en [archive/IMPROVEMENT_BACKLOG_CERRADOS.md](archive/IMPROVEMENT_BACKLOG_CERRADOS.md) y [archive/IMPROVEMENT_BACKLOG_INFORMES_DE_PLAN.md](archive/IMPROVEMENT_BACKLOG_INFORMES_DE_PLAN.md): congelados, no se les añade nada.
